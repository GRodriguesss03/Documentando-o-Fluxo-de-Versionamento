# 🚀 Ciclo de Vida de um Projeto no GitHub

## 📌 Introdução

Entendi que o GitHub é uma ferramenta importante para organizar, versionar e compartilhar projetos. Durante o estudo, aprendi como enviar um projeto, documentá-lo e realizar atualizações.

## 🚀 1. Criação e Envio
### 👤 1. Configuração Inicial do Git
Primeiro, crio um **repositório no GitHub**, definindo nome, visibilidade (público ou privado), depois conecto a pasta do meu computador ao repositório usando o Git.
Abra o seu terminal e defina a sua identidade global (utilize o mesmo e-mail cadastrado na sua conta do GitHub):
```
Bash

git config --global user.name "Seu Nome"
git config --global user.email "seu_email@exemplo.com"
 ```
Com isso, os arquivos que estão no meu computador passam a aparecer no repositório do GitHub.

---

## 📖 2. README.md

A criação de um **README.md** é importante para se ter um resumo do que será visto e como utilizar o projeto.

Considero importantes estas informações:

- * **Título:** identifica o projeto.
- * **Descrição:** explica seu objetivo.
- * **Tecnologias:** mostra o que foi utilizado.
- * **Instalação/execução:** ensina como utilizar.
- * **Status:** informa se está concluído ou em desenvolvimento.
- * **Licença:** define como o projeto pode ser utilizado.

O **Markdown** facilita a organização porque permite criar títulos, listas, tabelas, links e blocos de código de maneira simples e visualmente organizada.

---

## 🔄 3. Atualizações: Commits e Pushes

Depois de modificar o projeto, posso atualizar o GitHub de diferentes formas.

### 🌐 GitHub Online

Permite editar arquivos diretamente pelo navegador. É útil para pequenas alterações, mas não é tão prático para projetos maiores.

### 💻 Terminal

É a forma tradicional de trabalhar com Git:

```bash
git add .
git commit -m "Atualização"
git push
```

### 🧑‍💻 VS Code

Permite visualizar as alterações e fazer **commit e push** pela própria interface, facilitando o processo durante a programação.

### 🖥️ GitHub Desktop

Possui uma interface gráfica que facilita visualizar alterações, criar commits e enviá-los para o GitHub.

---

## 🧠 A Filosofia da Atualização

Com esse estudo, entendi que o **Git controla as versões do projeto**, enquanto o **GitHub permite armazená-lo e compartilhá-lo na nuvem**. Também percebi que o README é importante para explicar o projeto e que existem diferentes maneiras de realizar atualizações.
Para mim, aprender Git e GitHub é importante porque ajuda a manter meus projetos mais **organizados, documentados e preparados para trabalhos futuros**.

**Meu principal aprendizado:** não basta criar um código; também é importante saber versionar, documentar e compartilhar o projeto para se criar um portfólio.
